## 8. Startup baseline

The accepted current behavior is automatic startup after Windows logon, including Rancher/Moby readiness checks, application startup, public connectivity repair and stable access through the existing Tailscale identity.

Any older instruction that requires manually running `CONNECT-CHATGPT.bat`, keeping a black window open, or generating a new MCP token on every startup is historical and superseded by the current stable-startup and token-preservation design.

## 9. Security and recovery invariants

- Do not display `.env`, passwords, passphrases, authorization values, MCP private URLs or tokens.
- Do not rotate the MCP path token without explicit approval.
- Do not rebuild or delete Tailscale identity without explicit approval.
- Do not prune Docker volumes.
- Before a Windows deployment, require an exact approved commit, matching Preview, a fresh verified final backup and isolated restore verification.
- Record deployment reports from the start of each attempt.
- If deployment fails after production changes begin, execute and verify rollback.
- Portable backups must be DPAPI-independent and must not store their passphrase.
