# 11 — سیاست و فهرست کامل کلیدواژه‌ها برای تحلیل PDP

## اصل مهم

در نسخه نهایی پروژه، کلیدواژه‌ها **نباید برای امتیازدهی داخلی و تصمیم‌گیری قطعی داخل Web App** استفاده شوند. تصمیم نهایی درباره اینکه یک مناقصه/استعلام در لیست پیشنهادی قرار بگیرد یا نه باید فقط توسط **OpenAI API** انجام شود.

نقش کلیدواژه‌ها در این پروژه فقط این است:

1. کمک به ساخت Prompt تخصصی برای OpenAI.
2. کمک به توضیح حوزه‌های کاری PDP در `Pars-Settings.store.json`.
3. کمک به جستجو، فیلتر نمایشی و دسته‌بندی بعد از تحلیل.
4. کمک به مدل برای تشخیص موارد مرتبط، نامرتبط و موارد دارای ریسک.

بنابراین:

```text
internalScoring: false
analysisEngine: openai-api-only
```

## 5. عبارات ابهام‌زا و false positive

این عبارت‌ها نباید باعث شود مدل فکر کند پروژه «مطالعات مهندسی» است:

- اسناد را مطالعه نمایید
- پیشنهاددهندگان مطالعه کنند
- شرایط مناقصه مطالعه شود
- مطابق اسناد پیوست
- مطابق مندرجات ذیل
- طبق مشخصات فنی
- بررسی قیمت
- پیشنهاد قیمت
- استعلام قیمت
- خرید
- تهیه و تأمین

مثال:

اگر عنوان باشد:
«استعلام قیمت LUBRICATOR مطابق مندرجات ذیل و شرایط استعلام پیوست»
این نباید به خاطر کلمه «شرایط» یا «مطابق» یا «پیوست» مرتبط تلقی شود.

## 6. قواعد تفسیری برای OpenAI Prompt

مدل باید این نکات را رعایت کند:

1. تصمیم فقط از روی وجود یک کلمه گرفته نشود.
2. اگر عنوان خدمات مشاور، طراحی، مطالعات، نظارت، مدیریت طرح یا امکان‌سنجی دارد، احتمال تناسب بالاتر است.
3. اگر عنوان صرفاً خرید کالا یا تجهیزات است، معمولاً رد شود.
4. اگر آگهی اجرایی است ولی عبارت‌هایی مثل طراحی، نظارت، مدیریت طرح یا خدمات مهندسی دارد، قابل بررسی است.
5. اگر کارفرما از نهادهای با ارزش بالا است اما عنوان مبهم است، priority می‌تواند «قابل بررسی» با confidence پایین یا متوسط باشد.
6. اگر پروژه با سوابق شاخص PDP مثل منطقه ویژه اقتصادی، منطقه آزاد، شهرک صنعتی، شهرک خورشیدی، ساختمان عمومی، دانشگاه، GIS یا ماده ۲۳ هم‌خوان است، matchedPdpExperience باید پر شود.
7. اگر اطلاعات کافی نیست، مدل باید `riskNotes` را پر کند و `confidence` را low یا medium بدهد.
8. خروجی مدل باید برای هر ورودی دقیقاً یک تحلیل بدهد.

## 8. نحوه استفاده در OpenAI Prompt

در Prompt سیستم باید گفته شود:

```text
کلیدواژه‌ها فقط context هستند و نباید جایگزین قضاوت کارشناسی شوند. تحلیل باید مفهومی باشد، نه keyword scoring.
```

در خروجی هم باید این فیلدها برگردد:

```json
{
  "code": "کد آگهی",
  "source": "مناقصه یا استعلام",
  "isRecommended": true,
  "score": 0,
  "priority": "بالا / قابل بررسی / کم‌اولویت / رد",
  "fitForPDP": "strong / medium / weak / reject",
  "category": "حوزه تخصصی",
  "reason": "دلیل فارسی کوتاه و کاربردی",
  "recommendedAction": "پیگیری فوری / بررسی اسناد / تماس با کارفرما / ارجاع به کارشناس / رد شود",
  "matchedPdpExperience": [],
  "riskNotes": "ابهام‌ها یا ریسک‌ها",
  "confidence": "high / medium / low"
}
```
